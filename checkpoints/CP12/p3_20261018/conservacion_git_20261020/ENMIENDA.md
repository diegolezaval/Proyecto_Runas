# Conservación alternativa: enmienda administrativa previa a M2

La pausa posterior a 921901d eliminó scratch y /tmp; no queda trabajador local ni Actions activo. La búsqueda de respaldos no encuentra un P3 11,2 completo. El transporte permanente 9,6 sigue siendo la última memoria interna reanudable; la frontera aprobada sigue en 8. La excepción del usuario sólo permite repetir 9,6→11,2. No ha comenzado esa repetición. El intento perdido, sus recibos y el fragmento incompleto se conservan como antecedentes. CP12 sigue abierto y CP11 aceptado.

Se conserva V1 sin sobrescribir. V2 cambia únicamente el tamaño de las partes de 760000 a 6000000 bytes y su etiqueta de esquema. No modifica ningún byte de la cápsula ni importa M2. La API ya aceptó un prefijo binario de 6000000 bytes (objeto 9f6e86530366d23a8bc93c87383594631564b0a8); ese prefijo NO es conservación completa. Las lecturas de salida se encuadran en 750000 bytes, divisibles por tres; se recogen sesiones parciales hasta finalizar y se verifica cada tamaño base64 antes de componer un objeto. El objeto devuelto debe igualar el SHA1 Git calculado localmente.

Antes de M2: controles nuevos del codec sobre más de dos partes; paquete de capacidad completo mayor que el perdido 11,2; publicación de todas las partes y manifiesto en esta rama; recuperación desde Git en un segundo árbol; reconstrucción idéntica; verificación del archivo 9,6 interior, los 283 payloads y auditoría DOP853 sin pasos. Los resultados y la implementación administrativa del trabajador deberán quedar publicados antes de autorizar la ejecución local. La capacidad se acredita por paquete, no para todo el horizonte.

No se borran archivos científicos ni históricos, no se cambian fuentes M2/P3, configuración, parámetros, tolerancias o puertas. Cualquier nuevo fallo de conservación detiene la evolución; no se repite otra física. En 11,2 el trabajador debe esperar guardado, recuperación y auditoría independientes antes de continuar hacia 16. Main y PR2 intactos.
